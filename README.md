# Heimdall Monitoring Stack

Helm package installed into the customer/service EKS cluster. The chart installs the LGTM monitoring components needed by Heimdall and exposes a single internal `single_gateway` Service for pull-query access.

Included components:

- kube-prometheus-stack for metrics, kube-state-metrics, node-exporter, Alertmanager, and Grafana
- Loki for logs
- Tempo for traces
- Grafana Alloy for cluster collection
- Heimdall `single_gateway` internal NLB service

## Install from Helm Repo

After GitHub Pages is enabled for this repository, use the Pages URL as the Helm repository:

```bash
helm repo add heimdall https://s-heimdall.github.io/monotoring_stack
helm repo update

helm upgrade --install heimdall-monitoring heimdall/heimdall-monitoring \
  --namespace monitoring --create-namespace \
  --set global.clusterName=skala3-cloud1-finalproj-team6 \
  --set global.installToken=<install-token> \
  --set global.connectionDirection=pull_query \
  --set global.singleGateway.service.type=LoadBalancer \
  --set-string global.singleGateway.service.annotations."service\.beta\.kubernetes\.io/aws-load-balancer-scheme"=internal
```

## PrivateLink

PrivateLink is generated by the Heimdall project-registration UI because it needs runtime values from the selected service VPC, AIOps VPC, allowed principal, and the NLB created by this Helm install.

The UI shows two Terraform blocks:

- service VPC: creates `aws_vpc_endpoint_service` from the `single_gateway` internal NLB
- AIOps VPC: creates `aws_vpc_endpoint` that connects to the service endpoint name

## Render

```bash
helm dependency update charts/heimdall-monitoring
helm lint charts/heimdall-monitoring
helm template heimdall-monitoring charts/heimdall-monitoring --namespace monitoring
```
